# Nacos adapter operational contract

Local and Nacos implement the canonical `provider.Provider` and `provider.WatchProvider` contracts. NacosProvider returns `provider.ProviderNacos` from Type; Bind follows the same source-independent Viper rules for every Provider; there is no binding adapter or automatic business validation. Production adapter code depends on provider contracts and core helpers, not the root confy package. The root confy package does not import the SDK. This adapter uses official `nacos-sdk-go/v2` pinned to `v2.3.6-0.20260917093256-70993e7b0590` (commit `70993e7b0590aee5299849315d01a92fd346f8ab`). This is an immutable upstream commit, not a floating master dependency. The tagged v2.3.5 release was rejected after a real reconnect race test; the pinned revision includes upstream atomic connection/state fixes. The module dependency graph includes the SDK's Alibaba/KMS dependencies even though this adapter rejects OpenKMS and does not provide KMS functionality.

`New` collects functional options and prepares one shared Viper. `loader.go` contains client initialization, fetching and the common `writeConfig` method. `Load` initializes the client once, then calls `refresh` to fetch and write the remote document. Watch notifications call the same `refresh` directly, without running initialization again. `writeConfig` uses `Viper.ReadConfig` to update the original instance before notifying Bind. The Viper decoder rejects empty documents before source replacement, so each document is parsed once. YAML is the default; JSON and TOML require WithFormat. Data ID extensions do not choose a parser. Empty/whitespace/scalar/sequence/empty-object documents are rejected. Group defaults to DEFAULT_GROUP; the public namespace is the empty SDK namespace ID. Namespace/Group/Data ID cannot contain filesystem separators or control characters because the SDK also uses them as cache file names. Remote `base` is an ordinary field, never a local inheritance path.

SDK callbacks only coalesce wakeups in a bounded channel. A single delivery goroutine re-reads the current remote value, so reordered SDK callback goroutines cannot apply stale callback content. Registration includes a post-subscription remote read and initial reconciliation. Failed reads retry with a one-second delay; an idle watcher performs an SDK consistency read every five seconds to recover missed/coalesced notifications. SDK owns subscription, authentication and transport reconnection; no custom long-poll protocol is implemented. Updates may coalesce and do not guarantee every intermediate version. `Load` and watch refresh the same Viper in place, replacing its source configuration layer while preserving explicit Set overrides. `ConfigMutex` shares the Viper lock with Confy; direct Viper users must also take it. `Watch(ctx, onChange, onError)` notifies after source replacement and delivers recoverable errors serially, outside provider/config locks. The watcher suppresses unchanged effective settings, including ENV/Set overrides, before notifying Bind. Business validation requires explicit cfg.Validate(), even after updates. Parse/blank-document errors preserve Viper. Bind failures preserve only the bound struct; Get still exposes the latest parseable source. Field decryption happens in the binding view, leaving source ciphertext in Viper. Repeated Watch calls retain the active subscription and its original callbacks/context. Watcher.Close is idempotent and safe inside callbacks; context cancellation also releases the subscription. Config owns the SDK client; there is no borrowed-client API.

Strict startup uses a fresh 0700 temporary directory for every Provider, with snapshot fallback disabled. `ClientConfig.CacheDir`, if set, is the **parent** of that private directory; existing snapshots and failover are never reused. Close and failed confy.New remove owned files. The SDK still persists **raw Nacos source content** during the Config lifetime: literal secrets stored in Nacos may therefore appear in this private cache. Use empty keys plus ENV/Secrets or Confy field ciphertext. This is not a zero-disk or memory-only SDK. A process crash can leave a private temporary directory requiring operational cleanup; it will never be used by a new Provider.

The SDK logger is process-global and logs raw configuration at info level and on some cache-write errors. The adapter installs a non-recording SDK logger on its first Load, also silencing other official SDK clients in the process. `ClientConfig.LogDir`, LogLevel and AppendToStdout do not override this safeguard; the adapter uses an owned private log path. Applications must not replace the SDK logger with a content-recording logger after initialization if they require this protection. Provider operations return safe phase/resource errors and asynchronous update failures use safe WithOnError summaries. Direct Bind decoder errors follow Viper and may include configuration values; handle them accordingly. SDK internal retry status is not fully observable through WithOnError. No SDK logger contains decoded ENV/Confy secrets in the integration fixture.

TLS is delegated to SDK ClientConfig.TLSCfg and ServerConfig.Scheme, with TrustAll rejected. HTTP and gRPC certificate verification and authorization require deployment-specific testing. The local r-nacos fixture has neither OpenAPI auth enforcement nor TLS, so those production checks remain unverified.

Run isolated integration fixtures (never existing business Data IDs):

```sh
export NACOS_INTEGRATION=1
export NACOS_SERVER_ADDR=127.0.0.1:8848
export NACOS_NAMESPACE_ID= # explicit empty value selects public
export NACOS_TEST_GROUP=CONFY_INTEGRATION
# Inject NACOS_USERNAME/NACOS_PASSWORD securely if required.
# Set NACOS_EXPECT_AUTH=1 only on an auth-enforcing test environment.
env -u GOROOT go test -tags=nacos_integration -count=1 -timeout=180s -v ./e2e
env -u GOROOT go test -race -tags=nacos_integration -count=1 -timeout=180s -v ./e2e
```

The current fixture supports plain HTTP/gRPC, not a TLS test environment. It creates unique confy-integration Data IDs, publishes and deletes only those, scans owned cache files for a test secret, and faults only its own proxy connections. An explicit tagged run missing required environment variables fails. Normal go test never accesses a server.
